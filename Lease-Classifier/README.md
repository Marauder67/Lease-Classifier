# EFG Lease Classifier

A diagnostic tool that reads an equipment-lease contract and classifies it across
**three independent regimes**:

| Regime | Question it answers | Possible verdicts |
|---|---|---|
| **GAAP (ASC 842)** | How is it reported on financial statements? | Finance Lease · Operating Lease |
| **Federal tax (IRC)** | Who owns it for tax? | True Lease · Conditional Sale |
| **UCC §1-203** | Is it a true lease or secured financing? | Article 2A True Lease · Article 9 Security Interest |

It is **diagnostic only** — it never gives legal or tax advice and never suggests
how to restructure a lease. Those guardrails are enforced in code.

This repository is the "workable model" behind the v1.1 governed prompt, turned
into a real service with an API your CRM can call.

---

## The one big idea (why this design is trustworthy)

A language model is used for **exactly one job**: reading the PDF and pulling out
the terms (payment amount, term, buyout price, governing law, etc.). That's the
`app/extraction/` layer.

**Everything that produces a verdict is plain, deterministic Python** you can read
and audit in `app/engine/`. The implicit interest rate, the present-value tests,
the thresholds, the pass/fail logic, the case-law citations — none of it is ever
generated by an AI. This is what makes the output reproducible and defensible.

The engine is validated against your real pilot case (Davalor Mold Lease #2025699):
it reproduces the solved implicit yield (8.17%), the present-value percentages, and
all three verdicts exactly. See `scripts/verify.py`.

## Quick start (for someone new to this)

You'll run a few commands in a terminal. On a Mac, open **Terminal** and paste
these one block at a time.

### 1. Get the code onto your machine
If you're reading this from the folder already, you're set. Otherwise, once it's
on GitHub (see below), you'd run `git clone <your-repo-url>`.

### 2. Install Python 3.11+ and the dependencies
```bash
cd efg-lease-classifier
python3 -m venv .venv          # a private sandbox for this project's packages
source .venv/bin/activate      # turn the sandbox on (do this each new terminal)
pip install -r requirements.txt
```

### 3. Prove the engine works — no API key needed
```bash
python3 scripts/verify.py
```
You should see `17/17 checks passed` and a printed report. This runs your Davalor
case through the engine and checks every number against the reference report.

### 4. Run the full test suite (optional)
```bash
pytest -q
```

### 5. Start the API
```bash
cp .env.example .env           # then open .env and paste your Anthropic API key
uvicorn app.main:app --reload
```
Now open **http://127.0.0.1:8000/docs** in your browser — FastAPI gives you an
interactive page where you can try every endpoint by clicking buttons. No code.

## Using it

### Classify a lease you've already turned into terms (no AI step)
`POST /classify` with a JSON body like `examples/davalor_2025699.json`. Add
`?format=markdown` for the plain report, or `?format=html` for the **branded EFG
report** (Bar & Shield logo, navy/red palette, Poppins headings — a print-ready,
self-contained page). See `examples/EFG_Lease_Classifier_Report_Davalor_2025699_branded.html`
for a live sample. Brand values live in `app/branding.py` (single source of truth).

### Classify straight from a PDF (uses Claude to read it)
`POST /classify/document` — upload the lease PDF and pass the extra facts (useful
life, end-of-term FMV, etc.) as a JSON string in the `user_inputs` form field.
Requires `ANTHROPIC_API_KEY` in your `.env`.

### The missing-input interview
Some facts a lease never states (estimated useful life, end-of-term fair value,
your reporting framework). The tool marks anything it can't determine as
**"Insufficient data"** rather than guessing. Supply those via `user_inputs`.

Full endpoint reference: [`docs/API.md`](docs/API.md).
How your CRM plugs in: also in `docs/API.md`.

## Putting it on GitHub (step by step)

You have a GitHub account but haven't done this before — here's the whole thing.

```bash
# 1. From inside the project folder, start tracking it with git:
cd efg-lease-classifier
git init
git add .
git commit -m "Initial commit: EFG Lease Classifier v1.1"

# 2. Create an empty repo on github.com (click "New repository",
#    name it "efg-lease-classifier", leave it empty — no README).
#    GitHub then shows you a URL like https://github.com/you/efg-lease-classifier.git

# 3. Connect your local folder to that repo and push:
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/efg-lease-classifier.git
git push -u origin main
```

That's it — refresh the GitHub page and your code is there. From then on, the loop
is: change files → `git add .` → `git commit -m "what I changed"` → `git push`.

**Important:** never commit your `.env` (it holds your API key). The included
`.gitignore` already prevents that.

## Governance guardrails (enforced in code, not just policy)

- **No restructuring output. Ever.** The engine has no code path that suggests
  changing a lease's terms. A test asserts the output contains no such language.
- **"Insufficient data" is a valid verdict.** Missing inputs are surfaced, never
  guessed.
- **Three regimes always separate.** They're computed independently.
- **Citations only from the controlled library.** The classifier physically
  cannot cite a case that isn't in `app/data/case_law_library.json`; unknown
  states raise a "library gap" flag instead of inventing authority.

---

## Editing the case-law library

`app/data/case_law_library.json` is versioned and human-editable. To add a state
or circuit, add an entry under `circuits` (with its `states` list) or
`state_specific`, bump the `version`, and re-run `pytest`. No code changes needed.
